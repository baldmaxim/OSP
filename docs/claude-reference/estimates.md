# Estimates — проектный справочник

> **Справочник, а не инструкция постоянной загрузки.** Ниже сохранено исходное описание проекта, включая историю решений и возможные устаревшие варианты. При противоречии ориентироваться на текущий код, миграции, тесты, новую задачу и корневой `CLAUDE.md`.

## ПСДЦ / ВОР (миграция 20260908)

Ведомость стоимости работ документа первого этапа (договор, ДС на изменение ВОР, ДС на доп. работы). Связь — `psdc.document_id` → `contracts.id`; в самом XLSX ID документа нет и не требуется.

- **Расчёт — только в базе** (`psdc_validate_internal`, NUMERIC, `round()` = Excel ROUND half-up на каждой строке). Браузер лишь читает XLSX и шлёт сырые ячейки. Не дублировать формулы на фронте.
- Процесс: `K = ROUND(ROUND(I,5)·ROUND(J,2),2)`, `M = ROUND(ROUND(I,5)·ROUND(L,2),2)`, `N = ROUND(J+L,2)`, `O = M` при `D = ДМ`, иначе `ROUND(K+M,2)`. Секция — агрегат процессов с № `«секция.»…` (текстовый префикс, 5.10 ∈ 5): `K` без ДМ, `M` со всеми работами. Итог — только из процессов. Скрытый `U = deleted` — строка не в расчёте; других статусов нет.
- **Жизненный цикл** `uploaded → validated|invalid → applied → deleted`, незавершённая загрузка → `cancelled`. Один `applied` на документ (уникальный индекс). Все изменения — SECURITY DEFINER RPC (`psdc_create/add_rows/validate/apply/cancel/delete`, пакет: `psdc_batch_*`), таблицы ПСДЦ клиенту только на чтение.
- **Сумма документа**: `contracts.psdc_total` (пишут только `psdc_apply`/`psdc_delete`, триггер `contracts_psdc_total_guard`). В JS — `effectiveDocumentAmount(doc)` в [contractAmendments.js](src/utils/contractAmendments.js); `effectiveValues`/`contractActualAmount` уже учитывают ПСДЦ. Ручная `contract_amount` не перезаписывается. Если грузите договоры для расчёта сумм — добавляйте `psdc_total` в select.
- **Статусы**: завершённое ДС (и договор, созданный после внедрения ПСДЦ) — сначала вернуть на доработку; старые завершённые договоры принимают первичную ПСДЦ. Правило — `psdc_document_lock_reason()`.
- **Предыдущая ПСДЦ** — ближайшая применённая вверх по родителям в той же ветке (`psdc_find_previous`); по ней сохраняются ID строк из столбца T.
- НДС — из документа (`psdc_document_vat`), подпись в файле только диагностика.
- Фронт: [src/utils/psdcWorkbook.js](src/utils/psdcWorkbook.js) (безопасное чтение XLSX, копия с подсветкой ошибок, экспорт с формулами, шаблон), [src/services/psdc.js](src/services/psdc.js), [src/components/psdc/PsdcPanel.jsx](src/components/psdc/PsdcPanel.jsx) (вкладка «ПСДЦ / ВОР» карточки), [src/pages/PsdcBatchPage.jsx](src/pages/PsdcBatchPage.jsx) (`/contracts/psdc-batch`), [src/utils/psdcMatching.js](src/utils/psdcMatching.js) (автосопоставление имён файлов).
- Исходные XLSX хранятся в S3 как `owner_type='general'`, `owner_id=psdc.id`, `doc_category='psdc_source'` (редеплой `s3-presign` не нужен).
- Предел — 25 000 строк на ведомость (проверка укладывается в `statement_timeout` Supabase).
- Старая таблица `contract_psdc_items` (float-расчёт) больше не используется интерфейсом.

**Тесты** (`npm run test:psdc`): поднимают временный локальный PostgreSQL 17+ (`initdb/pg_ctl/psql` в PATH или `PG_BIN`, иначе Docker) с настоящими миграциями 20260906 + 20260908, проверяют движок, XLSX, интеграцию с суммами и UI в Chrome/Edge через Playwright (`PSDC_BROWSER`). Замер: `npm run bench:psdc`.

документом; пример — ЖК Примавера, корпус 14 (файлы «Примавера К14 - КП до перекидок.xlsx» и «Смета.xlsx»; в git их нет —
репозиторий открытый). Блок — над прежней «Сметой объекта» (`object_estimate_items`, не тронута).
**13.11.2026 упрощено** (пользователь: «сделать попроще всё пользование», «убери дублирующую информацию»): одна таблица
вместо видов «КП» / «ПЗ» и переходов между ними, без дерева разделов, плиток, панели фильтров, выбора столбцов, ответственного,
кол-ва заказчика, договора и «закреплённого объёма»; строка открывается окном; «во весь экран» — значок справа сверху.

- **Файлы.** КП (лист «Комм. затраты») — укрупнённые позиции по системам; вложенность — по диапазонам SUBTOTAL, а не по
  кодам (у подробных позиций укрупнённой «1.8.4.1 Отделка пола автостоянки» коды 1.8.2.8.x, у вставок «584.1» кода нет); без

  те же позиции с прямыми затратами ПЗ; связь — «№ п/п» = «Номер позиции» КП (у К14 3144 из 3145, последняя —
  «Округление», в итог КП не входит). **Один файл «КП + план затрат»** (13.11: пользователь прислал «переработанный файл»,
  до сессии он не дошёл — раскладка не проверена): `detectEstimateWorkbook` → `'both'`, если в книге есть и лист КП, и лист
  «Смета», или у листа КП справа столбцы прямых затрат («Прямые затраты», «Прямые: основные материалы» …, `pzInline`) —
  тогда план затрат берётся из той же строки. Два файла по-прежнему принимаются. Один файл сохраняется один раз (обе ссылки
  версии — на него). Формулы файла сверяются при разборе; паспорт, коэффициенты и сверка — «Паспорт и коэффициенты» в строке
  версии. К14: 3808 строк, формулы — 0 расхождений, итог 15 800 025 574,65 ₽; разбор ~1,2 с, показ после загрузки ~0,4 с.
- **Таблица** (одна, [columns.js](src/components/kpEstimate/columns.js)): Код | Наименование | Кол-во (ГП) | Актуальный |
  Стоимость КП | Прямые затраты | Свободно | Тендер и подрядчик | Примечание. Коммерция ПЗ = стоимость КП (у К14 0 расхождений) —
  не дублируется; цена, материалы / работы, разбивка прямых затрат — в окне строки. **Наименование целиком, одной строкой**
  (просьба 13.11): ширина столбца — по самому длинному видимому наименованию (canvas, кэш на шрифт), столбцы после него
  закреплены справа (`kpe-pin-r`), если под наименование остаётся ≥ 18rem; длинное уходит под них — при наведении
  показывается целиком поверх (`kpe-peek`, портал, мышь не ловит), дочитать — прокруткой вбок. Узкое окно — без закрепления.
  «Стоимость КП» и её итог — только строки КП (строка «Округление» сметы ПЗ — нет, иначе итог К14 на 0,32 ₽ меньше).
- **Объём** (`positionState`): исходный — **только «Количество (ГП)»** (13.11, пользователь: «кол-во заказчика не важно;
  исходный объём и кол-во заказчика — это разное»; у К14 324 позиции с кол-вом заказчика без ГП — все с нулевой стоимостью);
  актуальный — уточнённый (`kp_estimate_marks.actual_qty`), в ячейке пусто, пока не уточнён; разница и причина — в подсказке
  и окне. Изменение актуального объёма распределений не трогает.
- **Распределение — одно окно**: тендер (может не быть; поиск по тендерам объекта, свой номер — тоже), подрядчик —
  выбрали тендер с одним победителем (`tender_winners`) — встаёт сам, победители — первыми в списке; объём (по умолчанию —
  весь свободный остаток). Строки складываются (тендер с двумя победителями — две строки); пара «тендер + подрядчик» у
  позиции одна (уникальный индекс, окно предупреждает заранее). Объём строки — `pz_qty`; у строк, записанных до 13.11
  (тендер и договор с двумя объёмами), — больший из `pz_qty` и `contract_qty` (`allocQty`), правка объёма обнуляет
  `contract_qty`. Колонки договора и ответственного в базе остались, интерфейс их не пишет. Свободно = актуальный −
  распределённый; меньше нуля — «Превышение» (подсветка, не запрет). Выделенные строки — «Тендер и подрядчик…»: каждой
  свободный остаток (`planTenderAllocation`, та же пара — объём растёт). Справочники окна — тендеры объекта, контрагенты,
  победители (договоры и сотрудники больше не читаются).
- **Отметки**: примечание (в ячейке — нажатие, Enter / Esc; без права — окно), заливка строки (флажки, Shift — диапазон;
  у группы — со всем составом) и ячеек (кнопка «ячейки» — протянуть прямоугольник). Поиск — по коду, наименованию,

## Excel Import/Export (xlsx)

SheetJS — файлом `vendor/xlsx-0.20.3.tgz` (и `server/osp-api/vendor/`): на npm версий с исправлениями нет, а сборка на
сервере не должна зависеть от CDN SheetJS. Обновление — новый файл из `cdn.sheetjs.com` и правка `package.json` в обоих местах.

Used in `TenderDetailPage.jsx`, `ContractorProposalsPage.jsx`, and BSM pages:

```javascript
import * as XLSX from 'xlsx'

// Import
const workbook = XLSX.read(arrayBuffer, { type: 'array' })
const data = XLSX.utils.sheet_to_json(workbook.Sheets[workbook.SheetNames[0]])

// Export
const ws = XLSX.utils.aoa_to_sheet([headers, ...rows])
const wb = XLSX.utils.book_new()
XLSX.utils.book_append_sheet(wb, ws, 'Sheet1')
XLSX.writeFile(wb, 'filename.xlsx')
```

**Estimate columns (tender import):** A=№ п/п, B=КОД, C=Наименование затрат, D=Ед. изм., E=Объем по виду работ, F=Общий расход

**Section detection:** Rows without code (Р or мат.) and without numeric data are automatically marked as sections (`is_section=true`). The `original_row_number` field preserves the original Excel row numbering. Sections display with highlighted styling as headers for groups of work items.

### Numeric Value Cleaning (BSMPage pattern)

Excel imports may contain formatted numbers with currency symbols and spaces. Use this pattern:
```javascript
const cleanNumericValue = (value) => {
  if (typeof value === 'number') return value
  let str = String(value)
  str = str.replace(/[₽$€¥£]/g, '')                    // Remove currency symbols
  str = str.replace(/[\s\u00A0\u2007\u202F]/g, '')     // Remove spaces (including non-breaking)
  str = str.replace(',', '.')                          // Decimal comma to dot
  str = str.replace(/[^\d.\-]/g, '')                   // Keep only digits, dot, minus
  return parseFloat(str) || 0
}
```
