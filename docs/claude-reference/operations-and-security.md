# Operations And Security — проектный справочник

> **Справочник, а не инструкция постоянной загрузки.** Ниже сохранено исходное описание проекта, включая историю решений и возможные устаревшие варианты. При противоречии ориентироваться на текущий код, миграции, тесты, новую задачу и корневой `CLAUDE.md`.

## Нагрузка на сервер (03.11.2026, миграция 20261220)

Задача пользователя: сократить потребление, не жертвуя безопасностью. Основано на замерах базы Яндекса: пересчёт реестра — 13 с и 223 МБ временных файлов, 137 раз в сутки (¾ активного времени базы); одна вкладка «Тендеров» — 14 тыс. прочитанных строк участников раз в 20 с.

- **Опрос таблиц** ([tablePolling.js](src/api/tablePolling.js)): снимок целиком — при открытии и раз в полчаса (страховка), за такт — `id` и отметка времени изменившихся (обычно пустой ответ), строки — только изменившиеся, число строк (удаления) — раз в 3 такта; без действий пользователя 5 минут — такт реже в 5 раз. События те же, `old` — прежняя строка из снимка. **Новая подписка `useRealtimeTable`:** у таблицы должна быть отметка, которую ставит триггер (`updated_at`, иначе `STAMP_COLUMN`), нет её — таблица читается целиком каждые 20 с; `columns` — если нужны не все колонки. У `tender_counterparties` отметка — миграция 20261220 (только база Яндекса); без неё страница работает чтением целиком. Тесты — `tests/osp-api/client-db.test.mjs`, настоящий PostgREST — `tests/db/table-polling.test.mjs`.
- **Фоновые задачи проверяют, менялось ли что-то:** счётчики записей `pg_stat_user_tables` (чтение каталога). Пересчёт реестра ([registryRefresh.js](server/osp-api/src/lib/registryRefresh.js)) берёт источники из зависимостей представлений; разбор ВОР — `runIfChanged` в [supplyImport.js](server/osp-api/src/lib/supplyImport.js). Всё непонятное — работа как раньше, раз в 6 часов — в любом случае. Счётчик приходит с задержкой в секунды: в тестах ждать, а не считать проходы.
- **Статика:** копии `.gz` делает сборка образа ([precompress-dist.mjs](scripts/precompress-dist.mjs)), nginx отдаёт их готовыми (`gzip_static`); весь сайт 7,0 → 2,1 МБ, первый вход 188 → 63 КБ. Новый файл для образа — строка в `.dockerignore` (там список разрешённого).
- **Журнал:** каждый запрос пишет nginx контейнера сайта (кроме статики и `version.json`); osp-api — только запись, отказ, сбой и чтение дольше 1 с, с именем таблицы. Шлюз отдаёт ответ потоком, в памяти службы не копит.
- **Проверено и не сделано:** `work_mem` при пересчёте не трогать — от 4 до 128 МБ те же 3 с на копии. Ленивая загрузка библиотек службы даёт 6 МБ из 94 — не стоит того. Проверка живости — `wget`, не `node -e`.

## Права разделов в шлюзе, файлы, журналы (11.11.2026, миграции 20270120 и 20270121, только база Яндекса)

Задача пользователя: права проверяет сервер, а не скрытая кнопка; минимальными изменениями, без новой инфраструктуры. Решения 11.11:
запись проверяется сразу, справочное чтение — неделю пробно (принятый риск), загрузка файлов по праву просмотра остаётся, предел
файла 100 МБ (РД и ВОР — 300 МБ), удаление файлов в функции Supabase отключено, поля плана затрат тендера — по просмотру «Тендеров».

- **Шлюз `/api/db`** — после `allow.json` право раздела на каждое действие, связанную таблицу в `select` и вызов функции: карта
  `server/osp-api/src/data/db-sections.json`, разбор — `src/lib/dbSections.js`, права пользователя — `src/lib/sectionRights.js` (как
  `osp_can()`, кэш 30 с). Подрядчик — только `allow-contractor.json`. Подробно — `server/osp-api/README.md`, «Права разделов в шлюзе».
  **Новая таблица или функция в `allow.json` — запись в карте** (иначе падает `tests/osp-api/db-sections.test.mjs`), для кабинета —
  ещё строка в `allow-contractor.json`. Режимы: `OSP_DB_SECTIONS_WRITE=enforce`, `OSP_DB_SECTIONS_READ_REFERENCE=log` (через неделю
  по журналу `db section would deny` — `enforce`). Наборы, которые проверяют не права, подставляют `tests/osp-api/lib/open-sections.mjs`.
- **Охват по объектам** — одно правило `osp_object_scope()` (20270120): `object_ids`, иначе прежний `object_id`, иначе роль
  `roles.object_scoped` (рукстрой, экономист объекта) — ни одного объекта, иначе все. Им считают и `dp_request_scope()`,
  `doc_check_scope()`, `psdc_object_in_scope()`. Договоры и всё, что к ним привязано (дочерние таблицы, пункты и споры согласования,
  вложения объекта), — условие охвата дописано к правилам (копия прежних — `osp_private.policy_backup_20270120`); `ContractsPage`
  отбирает объекты и в запросе.
- **Файлы** (`routes/s3Presign.js`): изменение и удаление — `CHANGE_RULES` (правка раздела по владельцу и категории; файл задачи —
  загрузивший, автор задачи, администратор), скачивание — владелец виден и `READ_RULES`; строки `s3_documents` видны по владельцу
  (правило базы), менять у строки можно только имя и описание, автора ставит сервер (триггер `s3_documents_user_guard`); прямая
  запись строк через шлюз закрыта, заметки снабжения — действие `supply-notes`. Загрузка: предел, подпись типа и длины, учёт
  незавершённых (`src/lib/uploadIntents.js`). В интерфейсе удаление — `canDelete` / `canDeleteDoc` у `S3DocumentList`.
- **Журналы:** `osp_private.data_audit_log` пишет триггер договоров, тендеров, контрагентов, заявок на ДС и на проверку, задач
  (20270121; переживает удаление строки, читает администратор SQL). Шесть журналов для экрана: автор, роль и время — от сервера,
  правки нет, удаление — только вместе с родителем.
- **Прочее:** `app_settings` — ключ пишет правка его раздела (`app_settings_write_guard`); свой профиль — `profile_update_own`;
  ключи API — `OSP_API_KEYS_SOURCE=db` (по умолчанию; `env` — только до миграции 20261111); выход с ошибкой сервера — не выход.
- База Яндекса — `migration/yandex/20270120_object_scope_files.sql`, `20270121_audit_trail.sql` (+ `.check.sql`), откаты —
  `migration/rollback/` с теми же именами. Порядок: `migrate`, затем `both`. Тесты — `tests/osp-api/db-sections.test.mjs`,
  `api-keys-source.test.mjs`, «права на файлы» в `server.test.mjs`, выход — `client-auth.test.mjs`, база —
  `tests/tender/access-hardening-db.test.mjs` (копия прода под одной учёткой).

## Доступ к API: ключи в «Администрировании» (миграция 20261111)

Решение пользователя 29.10.2026: ключи API для смежных систем выпускает и контролирует администратор на сайте, по
образцу раздела «Доступ к API» другого портала, но с правами нашего API. «Администрирование» (`/admin`) → вкладка
«Доступ к API» ([ApiKeysTab](src/components/admin/ApiKeysTab.jsx), видна `isAdmin` / `isSuperAdmin`; подписи и
проверки формы — [utils/apiKeys.js](src/utils/apiKeys.js), запросы — `apiKeys` из `src/api` ([apiKeysClient.js](src/api/apiKeysClient.js))).

- **Права ключа** — ресурсы `/api/rates/*`: «Расценки от подрядчиков (КП)» (`kp`), «Расценки от снабжения СУ-10»
  (`supply`), «Договорные расценки (Larix)» (`larix`); только чтение. Перечень — `API_RESOURCES` в
  `server/osp-api/src/lib/apiKeys.js` и CHECK `scopes` в миграции (совпадение сторожит тест). **Новый ресурс API —
  это публикация данных:** новая миграция с расширенным CHECK + ресурс в `rates.js` / `API_RESOURCES`, по решению пользователя.
- **Ключ** `osp_` + 43 знака показывается один раз — окно после выпуска закрывается только кнопкой; в базе — sha256 и
  `osp_` + 8 знаков (`osp_private.api_keys`, правило по строкам — только служебные операции osp-api). Срок «Действует
  до» — последний день по Москве. Отзыв — сразу и навсегда; «Удалить» — убрать из списка (ключ отзывается, журнал
  остаётся). Отказ ключу — 401 с `code` `OSP_API_KEY_REVOKED` / `_EXPIRED` / `_REMOVED`.
- **Ключи из `RATES_API_KEYS`** продолжают работать; служба при запуске заносит их в список («Ключ из настроек
  сервера № N»): переименовать и отозвать — в портале, права и срок — только строкой на сервере (409).
- **Журнал вызовов** (`osp_private.api_key_calls`, 90 дней): время, ключ, ресурс, код, причина отказа, строк, время
  ответа, адрес; в списке ключей — «N за сутки», отказы, последний вызов.
- Сервер — маршруты `/api/admin/api-keys*` (`require: 'admin'`), раздел в `server/osp-api/README.md`. Только база
  Яндекса (`migration/yandex/20261111_api_keys.sql` + `.check.sql`); прежнему порталу не нужна — там вкладка
  подсказывает открыть tender.su10.ru. Без миграции: вкладка — «не применена миграция», ключи из строки — как раньше.
- Тесты: `tests/osp-api/api-keys.test.mjs` (настоящий PostgreSQL), права маршрутов — `tests/osp-api/access.test.mjs`
  (эталоны `tests/osp-api/baseline`), вкладка — `tests/tender/api-keys.test.mjs` (стенд `route=/stand/api-keys`,
  «сервер» в памяти — `tests/tender/ui/api-keys-stand.jsx`; `apiKeys=missing`, `apiKeysMany=N`).
