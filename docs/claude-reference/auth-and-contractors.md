Страница входа `/partner` не менялась. Тест — «контакт для связи и каналы» в `contractor-signup-ui.test.mjs`.

**Сейчас — заявки вручную** (05.11.2026, решение пользователя: «заводить подрядчиков вручную, сами одобрять поступающие заявки, без авторегистрации по почте»; режим `OSP_CONTRACTOR_SIGNUP_MODE=manual`, значение по умолчанию; почта и SMTP не нужны, миграции сверх 20261203/04 нет). Описанное ниже про письма — режим `email`, на потом: код и тесты остаются.

- **Путь:** заявка на `/partner/register` без пароля → сразу в «Администрировании» → «Регистрации подрядчиков», письма нет → «Открыть доступ» → окно с контрагентом → **временный пароль один раз** (как «Добавить пользователя», показывает `TemporaryPasswordDialog`), его передаёт администратор → при первом входе подрядчик меняет его на свой (`must_change`). Отказ — без письма. Забыл пароль — «Сбросить пароль» у администратора; ссылки «Забыли пароль?» нет.
- **Почему так:** почта заявителя не подтверждена, а ИНН общедоступен, поэтому доказательство одно — администратор проверяет человека по контактам из карточки компании или открытых источников, а не из заявки; окно об этом пишет. Проверки те же, что в режиме писем, но итог — не решение, а подсказка в «Что проверить» (`reasons`: `new_company`, `contact_matches`, `contact_differs`, `account_exists`, чёрный список и связи с ним, прежний отказ…). Компанию в ЧС одобрить нельзя, сервер отказывает.
- **Контрагент:** ИНН нашёлся в реестре — учётка к этой компании. Не нашёлся — новый контрагент (`registered_via='self'`) или выбранный в окне: в реестре бывают компании с пустым ИНН, иначе появился бы дубль; поиск начат сам по названию без формы собственности. Сервер не даст выбрать чужого при совпавшем ИНН, удалённого и из ЧС.
- **Что неизменно:** ответ заявителю один, что бы ни нашлось (`202 { ok: true }`), учётка всегда `self_registered` с коротким списком шлюза, пароль в заявке не принимается. Цена отказа от подтверждения почты — очередь можно засорить, поэтому пределы ниже: 50 заявок в сутки всего, 5 с адреса (`SIGNUP_MANUAL_DEFAULTS`). Адреса ссылок из писем и восстановления пароля отвечают 404, очередь писем не запускается.
- **Страница:** режим отдаёт `/api/auth/config` (`signupMode`), фронт спрашивает `signupManual()`. Тесты — блок «режим „вручную“» в `tests/osp-api/contractor-signup.test.mjs`, два «режим „вручную“» в `tests/tender/contractor-signup-ui.test.mjs` (стенд `signupMode=manual`, вкладка — ответ `mode: 'manual'`).

- **Поля заявки** (05.11.2026, решения пользователя; миграция 20261229, только база Яндекса; правила — общие со службой):
  - **Форма организации подрядчику выбирать не нужно** (решение пользователя: «чтобы он сам не выбирал из огромного списка»): название пишут как привыкли, форма встаёт в колонку слева сама. Сначала — слово в начале названия (`splitLegalForm`, сокращением или целиком; `LEGAL_FORMS`: ООО, ИП, СЗ — самозанятый, АО, ПАО, ЗАО, ОАО, НАО, АНО, ГУП, МУП, ФГУП, ГБУ): оно уходит в колонку и из названия; на копии реестра 15.10 форму пишут только в начале (1172 из 1854, в конце — ни одной). Нет слова — по ИНН (`guessLegalForm`, только на странице): 12 цифр — ИП, 10 — ООО (99 % и 94 % среди компаний с формой и ИНН); рядом подсказка «определена по ИНН», догадка не сбивает названную форму и не ограничивает длину ИНН. Список в колонке — только поправить, при известном ИНН в нём лишь подходящие формы (`legalFormsForInn`), «—» убирает форму. Форму из слова берём, пока её никто не назвал: у «ООО СЗ Инвест» второе слово — часть названия; очистил название — форма снова определяется сама. В заявке, реестре и карточке — вместе: «ООО Ромашка». Запрос: `legalForm` (код; `''` — без формы, название как есть; нет поля — из названия; сама служба по ИНН форму не ставит) + `companyName`. Новая форма — строка в `LEGAL_FORMS` (и слово в `companyNameKey`, `nameForSearch`).
  - **ИНН** — только цифры, в том числе на сервере; длина — по форме, если она названа (10 у организаций, есть КПП; 12 у ИП и СЗ). **КПП** — 9 знаков, в 5–6 знаках ФНС допускает заглавные латинские буквы (`isValidKpp`, в поле — `cleanKppInput`: русские А, В и другие похожие заменяются на латинские). Предел — в обработчике, а не `maxLength`: тот обрезал бы вставленное «ИНН 7707…» до очистки.
  - **Телефон** — «+7» стоит перед полем, вводятся 10 цифр, маска — `formatPhone`, курсор при правке на месте (`showKeepingCaret`). Привычные 8 и +7 убираются (`parsePhoneInput`), коды 812 и 701 остаются. Добавочный — до 6 цифр, той же записью, что у контактов: `+79161234567 доб. 123` ([phoneFormat.js](src/utils/phoneFormat.js), теперь в `SHARED_FILES`), её пропускает расширенное миграцией ограничение `registrations_phone_check`. **Сравнивать номера — только через `phoneMainDigits`:** последние 10 цифр всей строки были бы цифрами добавочного, и сверка с контактами из чёрного списка перестала бы срабатывать. Номер других стран страница не даёт ввести; сервер принимает его с «+», а после «+7» — ровно 10 цифр (раньше «+7 916 123» проходил как зарубежный).
  - **Почта** — до 100 знаков, без «@» — своё замечание. Телефон и почта проверяются при выходе из поля.
  - База Яндекса — `migration/yandex/20261229_signup_phone_ext.sql`, откат — `migration/rollback/20261229_signup_phone_ext_rollback.sql`. Порядок: `migrate`, затем `both`: без миграции заявка с добавочным не запишется. Тесты — `tests/osp-api/signup-rules.test.mjs`, `contractor-signup.test.mjs`, `tests/tender/contractor-signup-ui.test.mjs`.

- **Пароль задаёт хозяин почты** на странице по ссылке из письма, видя компанию и ИНН; в заявке пароля нет и быть не должно: иначе чужой человек указал бы чужую почту и свой пароль.

## Свой вход tender.su10.ru (AUTH_MODE)

Новый портал входит без Supabase Auth: учётки — `auth.users` базы Яндекса (те же id), пароли — закрытая схема
`osp_auth` (только отметка `osp:auth`, зашифрованы ключом `OSP_AUTH_KEYS`), сессии — `osp_session`, cookie
`__Host-osp_session` + CSRF `__Host-osp_csrf`. osp.root.sx остаётся на Supabase. Режим — `AUTH_MODE`
(`supabase` | `both` — пилот | `own`), фронт узнаёт его из `/api/auth/config` только при `authServer: true` в
`config.json`. Фронт: фасад `src/api/auth.js` (Supabase или `ownAuth.js`), `session.js` (CSRF, события сессии),
`authMode.js`; `RoleContext` (временный пароль, окно повторного входа), `ChangePasswordForm`, `ReloginModal`,
«Добавить пользователя» / «Сбросить пароль» в `AdminPage`. Сервер: `server/osp-api/src/lib/auth/*`,
`src/lib/principal.js`, `src/routes/auth.js`; миграция `migration/yandex/20261019_own_auth.sql`; перенос паролей —
`migration/accounts/`; порядок — `migration/CUTOVER.md` («Свой вход tender.su10.ru»). Сотрудникам учётки и временные
пароли выдаёт администратор; подрядчик может зарегистрироваться сам — см. «Регистрация подрядчика на сайте». Роль в окне нового пользователя по умолчанию — «Гость»
(`guest`, 02.11: подставлялся первый в справочнике — «Администратор»); «Гостя» в справочнике нет — роль выбирают сами
([AccountModals](src/components/admin/AccountModals.jsx)). Тесты: `tests/osp-api/own-auth*.test.mjs`,
`client-auth.test.mjs`, `tests/backup/own-auth-accounts.test.mjs`, `tests/tender/add-user-role.test.mjs` (стенд
`route=/stand/add-user`, `addUserNoGuest=1`).

## Вход через Keycloak su10 (AUTH_MODE=keycloak, миграция 20270112, только база Яндекса)

Решение владельца контура 06.11.2026 (пересмотр 15.10): вход tender.su10.ru — единый вход СУ-10 (auth.su10.ru, OIDC, BFF;
задача — `temp/osp-oidc.md`). Решения пользователя: вход «через Яндекс» (`own`) остаётся и переключается в обе стороны командой
`scripts/deploy-server.sh auth-mode own|keycloak` (около минуты, без сборки, связи и заявки сохраняются); права разделов в шлюзе
(раздел 4 задачи) — вторым выпуском, с пробным режимом (09.11); роль «Администратор» выдаёт и связывает с СУ-10 только
суперадминистратор (10.11) — маршруты и триггер базы `user_roles_admin_guard`. Устройство — `server/osp-api/README.md` («Вход через
Keycloak su10», «Замок сайта и PostgREST по сокету»), порядок и стоп-условия — `migration/CUTOVER.md`.

- **Учётка прежняя:** связь `(issuer, sub) → auth.users.id` — `osp_auth.identity_links`; заявки администратору —
  `osp_auth.identity_requests` («Администрирование» → «Заявки на доступ», [IdentityRequestsTab](src/components/admin/IdentityRequestsTab.jsx),
  пометка «СУ-10» у пользователя, «Отвязать»; организация сопоставлена с контрагентом — в «Создать пользователя» роль только «Подрядчик»,
  решение пользователя 25.11.2026: выводится из состояния организации, сопоставить можно и при открытой форме). Пользователей сами не создаём, по почте привязываем только в окно
  (`OIDC_LINK_BY_EMAIL=true` — после письменного подтверждения auth в CUTOVER) и никогда — администраторов.
- **Организация учётки СУ-10 → контрагент** (11.11.2026, задача auth `temp/osp-org-mapping.md`, план ред. 2 после рецензии; миграция
  20270201, только база Яндекса; [orgs.js](server/osp-api/src/lib/auth/orgs.js), подробно — `server/osp-api/README.md`): claim
  `su10_org_id` access token + кэш реестра `/org` (`osp_auth.su10_orgs`, `active | missing | invalid`) + связь 1:1
  (`osp_auth.org_links`). Подрядчик входит только при действующей связи (контрагент ставит сервер, `counterparty_source='su10'`;
  без связи — `org_unmapped`, контрагент не трогается и не NULL); **сотрудник — только со своей организацией СУ-10** (решение
  пользователя 11.11; исключение — суперадминистратор, `org_exceptions`). **Связывает только администратор** («Администрирование» →
  «Организации СУ-10», [Su10OrgsTab](src/components/admin/Su10OrgsTab.jsx), окно [Su10OrgMatchDialog](src/components/admin/Su10OrgMatchDialog.jsx),
  блок в карточке контрагента [CounterpartySu10Org](src/components/counterparty/CounterpartySu10Org.jsx); работает и в `own` —
  связи готовят заранее): автоматической связи нет — в выгрузке auth нет ИНН реестра (решение пользователя 11.11); отчёт с
  подсказками — `migration/org-links/build.mjs`, вне git (в выгрузке ФИО ИП — CSV в git не класть, `temp/su10-orgs-*.csv` в
  `.gitignore`). Отвязка, ЧС и удаление контрагента, смена `counterparty_id` любым путём и выбывание из реестра закрывают сессии
  сразу; контрагента учётки СУ-10 мимо сервера не поменять (триггер, 42501; в карточке пользователя при `ssoAuth` — только показ).
  Тесты — `tests/osp-api/su10-orgs.test.mjs`, `org-match.test.mjs`, `tests/tender/su10-orgs.test.mjs` (стенд `route=/stand/su10-orgs`).
- **Сессии** (`osp_session.sessions.auth_source`): `own`/`both` принимают только парольные, `keycloak` — только СУ-10; чужой вид —
  401 `OSP_AUTH_MODE` (перезагрузка вкладки). Сессию СУ-10 продлевает только действие: `X-OSP-Activity` = CSRF (ставит

- **Фронт:** [authMode.js](src/api/authMode.js) — `isSessionAuth` (своя сессия), `isPasswordAuth` (пароль ОСП: форма, смена пароля,

  обложки объектов в режимах своей сессии — только вошедшему сотруднику (`Cache-Control: private`); выпуск 0 — osp-api в общей сети
