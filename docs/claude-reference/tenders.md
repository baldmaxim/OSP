# Tenders — проектный справочник

> **Справочник, а не инструкция постоянной загрузки.** Ниже сохранено исходное описание проекта, включая историю решений и возможные устаревшие варианты. При противоречии ориентироваться на текущий код, миграции, тесты, новую задачу и корневой `CLAUDE.md`.

## Завершение тендера ОС: понятийное соглашение (миграция 20261210)

Решения пользователя 03.11.2026: только «Тендеры — Основное строительство»; без подписанного понятийного соглашения тендер не закрыть;
победитель обязателен, его можно выбрать из участников, из базы контрагентов или добавить вручную. ГО, совместные, «Прочее» и тендеры на материалы завершаются как раньше.

- **Окно завершения** (выбор «Завершен» в реестре, то же окно выбора победителей в TendersPage, заголовок «Завершение тендера»): вопрос «Понятийное соглашение подписано?» ([ConceptAgreementStep](src/components/ConceptAgreementStep.jsx)), выбор победителя не из участников ([WinnerFromBase](src/components/WinnerFromBase.jsx)), «Завершить тендер» неактивна, пока нет победителя и файла, причина написана над кнопками. Статус «Завершен» в форме тендера у ОС не пишется: остальная правка сохраняется, открывается это окно (форма из карточки — в карточку после окна). Уже завершённые не спрашиваем: старые закрыты без соглашения.
- **Шаблон подгружается сам при открытии окна**: карточка `tender_docs` «Понятийное соглашение» во вкладке «Документы» тендера и в ней копия файла по ссылке `concept_agreement_template_link` (`doc_category` `concept_agreement_template`). Отмена окна их не убирает: шаблон нужен, чтобы подписать. Документ закрыт — в карточку идёт ссылка (`tender_doc_links`) и окно называет причину; ссылки нет или это сетевой путь — окно об этом говорит, загрузке подписанного это не мешает.
- **Подписанное** — файл той же карточки с `doc_category` `concept_agreement_signed` (PDF, Word, скан, до 50 МБ). Файл, добавленный через вкладку «Документы» в эту карточку, — тоже подписанное. Правила и категории — [tenderConceptAgreement.js](src/utils/tenderConceptAgreement.js), запросы — [services/tenderConceptAgreement.js](src/services/tenderConceptAgreement.js). Проверяется наличие хотя бы одного файла: при нескольких победителях окно только просит загрузить соглашение с каждым.
- **Победитель не из участников** в `tender_counterparties` не добавляется, только `tender_winners`: он не участвовал, отчёты по участию это не должно исказить. Поиск — вся база, кроме удалённых, статус «Малые суммы» и «Чёрный список» виден в строке. Добавить контрагента вручную (название, ИНН необязателен) может тот, кто завершает тендер, даже без права правки «Контрагентов»; запись — в журнал контрагента.
- **Запрет в базе** — триггер `tenders_concept_agreement_guard` (обе базы; права вызывающего; `P0001` с `tender_winner_required` / `concept_agreement_required`): только переход в «Завершен», только ОС; без вошедшего — без проверки. Держит открытые старые вкладки и любую другую запись. Меняете категорию файла — меняйте и триггер. База Яндекса — `migration/yandex/20261210_tender_concept_agreement.sql`; проверка — `migration/backup/checks/20261210.sql`, откат — `migration/rollback/20261210_tender_concept_agreement_rollback.sql`. Порядок: `migrate`, сразу затем `both` (между ними старая страница получает отказ базы).
- Тесты — `tests/tender/tender-concept-agreement.test.mjs` (стенд `route=/tenders/construction`), `tender-concept-agreement-db.test.mjs` (слепок и копия под одной учёткой).

## Общий шаблон письма подрядчикам, ОС (18.11.2026, без миграции)

Просьба пользователя: «возможность менять шаблон письма для администратора в /tenders/construction». Раньше шаблон жил только
в браузере (`localStorage` `letterTemplate:v4`) — у каждого свой, и правка администратора до коллег не доходила. Теперь в ОС
один общий шаблон — моё толкование просьбы; решение о том, что остальным он только для чтения, — тоже моё.
- **Хранение** — `app_settings`, ключ `tender_letter_template:construction` ([tenderLetterTemplate.js](src/utils/tenderLetterTemplate.js),
  запросы — [services/tenderLetterTemplate.js](src/services/tenderLetterTemplate.js)). Ключ не отнесён ни к одному разделу в
  `app_settings_key_sections` — в базе Яндекса его пишет только администратор (триггер `app_settings_write_guard`, 42501;
  **только с миграцией 20270120** — без неё и на прежнем портале запрет держат одни кнопки страницы, как у
  `tender_responsible_override`: прямым запросом ключ записал бы любой сотрудник). Новый ключ с началом `tenders_root_folder_path` / `tenders_drive_folder_link:` стал бы
  доступен правке «Тендеров» — так не называть (сторожит тест).
- **Вкладка «Шаблон письма»** («Документы» → «Материалы», TendersPage; кто что видит — `letterTemplateView`): администратор правит
  черновик и пишет «Сохранить для всех»; «По умолчанию» — записать текст по умолчанию всем (после вопроса); пустой и длиннее
  20 000 знаков — отказ; общий не прочитался — править нельзя (иначе текст из браузера лёг бы поверх). Общий задан — остальным
  только чтение, свой текст из браузера не действует. **Общего ещё нет — всё как раньше** (свой шаблон в браузере у права правки
  «Тендеров»; у администратора в поле — его прежний текст, чтобы сохранить его всем). `upgradeLetterTemplate` к общему не
  применяется: вернул бы строки, которые администратор убрал.
- **Письмо** (строка реестра и «Письмо подрядчикам» в форме) перечитывает общий шаблон при каждом открытии — правку администратора
  коллеги получают без обновления страницы; не прочитался — последний прочитанный, иначе свой из браузера.
- **Только ОС:** ГО, совместные и «Прочее» — прежний шаблон в браузере (страница одна на все направления, поэтому что применять,
  считается от `department`, а не хранится в состоянии).
- Выкладка — `frontend` (карта шлюза `db-sections.json` — только описание ключа). Тест — `tests/tender/letter-template.test.mjs`
  (стенд `route=/tenders/construction`, `sharedLetter=1`, `asRole=engineer`).
