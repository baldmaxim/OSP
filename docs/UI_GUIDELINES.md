# UI: правила типографики и таблиц

Ориентир — GitHub Primer Product UI: рабочий интерфейс с плотными таблицами,
в приоритете читаемость, компактность и предсказуемость. Brand-стили,
градиенты, декоративные карточки, крупные тени и цветные блоки не используем.

## Где действует

| «Тендеры — Прочее» | `/tenders/other` | то же, с 29.10.2026; плотный вариант ОС (см. ниже) |

Остальные страницы — на прежней типографике. `TendersPage` рендерит и
гарантийный отдел и совместные тендеры: у них `uiWork = false`, и
рабочий стиль не включается (бывшие инлайн-стили вынесены в классы
`Tenders.css` с прежними значениями). «Прочее» с 29.10.2026 — на рабочем стиле.

**Подключить новый раздел:** корню страницы — класс `ui-work`; в компоненте —
`useBodyClass('ui-work-portal')` (для всплывающих окон); импорты
`../styles/fonts.css` и `../styles/workUi.css` **после** CSS страницы;
ширины колонок — в CSS самой страницы (см. «Таблицы»).

## Файлы

- `src/styles/workUi.css` — общий слой: токены `--ui-*` (на `:root`), шапка,
  вкладки и счётчики, панель поиска и фильтров, таблица, ссылки, статусы,
  пустые значения, срок, фокус, окна, порталы. Правила — под `.ui-work.ui-work`
  (повтор класса поднимает специфичность, чтобы вид не зависел от порядка
  подгрузки CSS других страниц); внутри таблиц — под
  `.ui-work.ui-work :is(.data-table, .dcr-table)`.
- Сетки и особенности разделов: `CostPlansPage.css` (`.cp-col-*`),
  `TendersRegistryPolish.css` (`.tp-c-*`, `.tp-mc-*`), `DcRequestsPage.css`
  (`.dcr-col-*`), `ContractRegistryPolish.css` (блок «Рабочий стиль» в конце) —
  всё под `.ui-work`.
- Компоненты: `ClampText` (3 строки + «Показать полностью»), `PersonName`
  («Фамилия И. О.» + полное для диктора), `BreakableId` (номер документа с
  переносом только после `/ - _ .`), `WrapSelect` (в `DcRequestsPage.jsx`:

## Шрифт

- **Inter 4.1** из официального релиза https://github.com/rsms/inter, лицензия
  SIL OFL 1.1 — `public/fonts/inter/LICENSE.txt`. Файлы отдаёт само
  приложение (`public/fonts/inter/`), внешний CDN не нужен.
  `@font-face` — `src/styles/fonts.css`.
- Начертания: **400** (текст), **500** (кнопки, фильтры, вкладки, заголовки
  колонок, статусы), **600** (заголовки раздела и блоков). Курсив не грузим.
- Семейство — **`Inter OSP`**, не `Inter`: `index.html` подгружает `Inter` с
  Google Fonts для остального портала, одноимённые `@font-face` смешались бы.
  Имя в `@font-face` и в `--ui-font` должно совпадать.
- Резервный стек: `'Segoe UI', system-ui, -apple-system, 'Helvetica Neue', Arial, sans-serif`.
- Символы, которых нет в Inter (▾ ▸ и т.п.), берутся из системного шрифта —
  в новых элементах стрелки и значки рисуем SVG.

## Шкала (токены `--ui-*`)

| Роль | Размер / интерлиньяж | Вес | Токены |
|---|---|---|---|
| Заголовок раздела | 20/28 (1.25 / 1.75 rem) | 600 | `--ui-title`, `--ui-title-lh` |
| Заголовок блока, окна | 16/24 (1 / 1.5 rem) | 600 | `--ui-block`, `--ui-block-lh` |
| Текст таблиц и форм | 14/20 (0.875 / 1.25 rem) | 400 | `--ui-text`, `--ui-text-lh` |
| Кнопки, фильтры, вкладки | 14/20 | 500 | `--ui-text`, `--ui-medium` |
| Заголовки колонок | 13/18 (0.8125 / 1.125 rem) | 500 | `--ui-th`, `--ui-th-lh` |
| Текст статусов | 13/18 | 500 | `--ui-th` |
| Вторичные подписи, пояснения | 12/16 (0.75 / 1 rem) | 400 (мелкие действия — 500) | `--ui-hint`, `--ui-hint-lh` |

Прочие токены: `--ui-control-h` (34px — поиск, фильтры, кнопки панели),
`--ui-radius` (6px), `--ui-cell-py` / `--ui-cell-px` (8px / 8px — отступы
ячейки), `--ui-link` (цвет текстовых ссылок, см. «Контраст»). В «ВОРах и РД»
токены `--vr-*` — псевдонимы `--ui-*`.

- Размеры — только в `rem`. Базовый размер шрифта браузера не переопределяем.
- Новых размеров «между» ступенями не вводить; акцент — вес 500/600 или цвет
  из существующих токенов.
- **Не уменьшать шрифт ради размещения таблицы** — сначала ширины колонок,
  отступы и переносы.

### Плотный вариант: реестр «Тендеры — Основное строительство»

Рабочий реестр на сотни строк со многими колонками этапов. Для него (и с
29.10.2026 — для «Тендеров — Прочее», по решению пользователя) действует плотный
вариант — класс `tp-dense` на корне (`TendersPage`: `denseRegistry = uiWork &&
!isMaterialsView`), правила — в конце `TendersRegistryPolish.css`. У «Прочего»
нет подразделения ВОР (плашка и фильтр — `divisionUi`, только ОС) и колонок «ВОРы
и РД», «План затрат», «Тендер на материалы»: свой `min-width` таблицы по классу
`tp-dept-other` (71,5rem — в окне 1280px без прокрутки). Токены `--ui-*` переопределены **внутри
шапки, вкладок, панели и таблицы** (включая раскрытую строку); окна и
всплывающие списки остаются на обычной шкале 14/20.

| Роль | Плотный вариант |
|---|---|
| Название раздела | 18/24, 600 |
| Данные таблицы | 12/16, 400 (ссылка на работы — 500) |
| Заголовки колонок | 11/15, 500 |
| Вторичные сведения (путь к папке, отметки, даты ВОР, «Показать адрес») | 11/15, 400 |
| Кнопки, фильтры, вкладки (вне таблицы) | 13/18, 500; высота кнопок и полей 32px |
| Статусы | 11/15, 500 (главный статус — плашка с отступами, этапы — плотнее) |
| Отступы ячейки | 6px; между элементами внутри ячейки 2–4px |

Шкала таблицы здесь на ступень мельче общей (12/16 против 14/20): реестр на
сотни строк, и прежний вид, к которому привыкли, был именно такой плотности.
Шапка, вкладки и панель остаются на 13/18 — мельчить их незачем. Это
единственное место, где заголовки колонок и вторичные подписи опускаются до
11px; данные ниже 12px не опускаются нигде.

Отличия от общих правил таблицы (ниже): **тонкие вертикальные разделители**
между колонками (цвет рамки 75%); описание работ — **акцентная ссылка с тонким
подчёркиванием**, 500; короткие подписи колонок («Объект», «Срок тендерных
процедур»), полный смысл — в `title`. Название и все действия шапки — в одну
строку на 1920; при нехватке места группа кнопок переносится целиком.
Данные не мельче 12px, `zoom` и `scale` не используем.

**Ширины — по замеру содержимого** (скрипт замера в стенде, не на глаз): каждая
колонка равна самому широкому неразрывному значению плюс отступы, а остаток
достаётся описанию работ. После того как адрес объекта убрали под кнопку,
«Объекту» хватает 10rem — освободившееся ушло описанию, а не осталось пустым.
Сумма фиксированных — 78rem, описание — 14rem (то, что ему оставалось в самом
узком окне), `min-width` таблицы 92rem: на 1720 реестр почти помещается в
рабочую область; окно шире (1920, свёрнутое меню) — растут все колонки
пропорционально, а не одно описание (30.10.2026).

**Ячейка описания — один блок текста и одна группа действий.** Ссылка на тендер
занимает свою строку, под ней в ряд идут «Показать полностью», путь к папке и
отметки (подразделение ВОР, «ТГ», письмо); переносятся только при нехватке
ширины. Раньше каждый элемент был отдельным блоком — три служебные строки на
запись, и высоту реестра задавало не содержание. Действия остаются разными:
переход по тексту, раскрытие полного описания, папка и «ТГ» — у каждого свой
обработчик. Подразделение ВОР (`VorDivisionChip`) — плашка размера «ТГ» со
списком выбора; это то же поле, что столбец «Подразделение» в «ВОРах и РД»
(`utils/vorDivisions.js`), пустое — пунктиром «Подразделение».

**Фильтр по подразделению — в заголовке «Описание работ»** (`VorDivisionFilter`),
рядом с подписью колонки: несколько подразделений и «Не указано», в списке —
число тендеров по реестру с остальными фильтрами. По умолчанию — «Все
подразделения», в том числе без подразделения (тихая пунктирная плашка).
Выбранный фильтр должен быть виден сразу: заливка и рамка акцентом, в подписи —
что выбрано («Монолит», «Подразделений: 2»), рядом кнопка сброса, у заголовка —
акцентная черта снизу (`th.tp-th-filtered`); «Сбросить все» панели его тоже
снимает. Сохраняется вместе с остальными фильтрами реестра. На телефоне шапки
таблицы нет — тот же фильтр в панели фильтров.

Ещё в плотном реестре:
- **«№» — одна служебная колонка**: номер и кнопка раскрытия сверху, счётчик
  участников/КП («0 участников», «3/10 КП») под ними. Освободившаяся ширина
  отдана «Объекту». `mainTableColSpan` учитывает объединение (−1).
- **Без переносов по слогам** (`hyphens: manual`): перенос по пробелам; слово
  длиннее колонки всё же переносится (`overflow-wrap: break-word`).
- **Адрес объекта скрыт** (в обычном и компактном виде): под названием —
  кнопка «Показать адрес» (`.tp-addr-toggle`, настоящая `button` с
  `aria-expanded`/`aria-controls` на `tp-addr-{id тендера}`), раскрытый блок
  `.tp-addr-block` — полный адрес и «Месторасположение». Свёрнутый блок —
  атрибут `hidden` (без высоты и без фокуса). Состояние — `Set` id тендеров в
  `TendersPage`, не сохраняется между заходами. Кнопка не вкладывается в
  ссылку на объект и не раскрывает тендер. Нет адреса — «Адрес не указан»
  без кнопки, ссылка на карту (если есть) видна сразу.
- **Раскрытый список участников:** заголовки вложенной таблицы 12/16, 600,
  тонкие вертикальные разделители, ячейки 6px 8px 13/18, всё по левому краю;
  примечание участника — 13/18 полным текстом, не курсив; статус 12/16, 500;
  «Добавить контрагента» и «Копировать email» рядом, высотой 28px;
  «Примечание по тендеру» — компактный блок, заголовок 12/16 600, правка и
  история справа.
- **Таблица участников** (`tc-table`, `ParticipantsTable.css`; реестр и карточка, 29.10.2026):
  колонки № · компания · «Контакты» · «КП / Документы» · примечание. В ячейке компании —
  название 14/20, 500 (выделяется размером, не жирностью), вид работ одной строкой с
  многоточием (ИНН — в подсказке названия), под ними статус участника плашкой по своей ширине.
  Каждый подрядчик — блок: все ячейки по верхнему краю, между подрядчиками черта
  `--border-color-dark`, через одного — подложка, подсветки по наведению нет. Колонки 15/15/28rem,
  таблица не уже 64rem — в узком окне прокручивается обёртка. Примечание в карточке — поле без
  рамки (пустое — пунктир с подсказкой).
- **«КП / Документы» участника** (`TenderCounterpartyFiles`, 29.10.2026; та же ячейка во вкладке
  «Участники» карточки): сверху строка-сводка — стрелка, «КП · N · M версий», справа «+ КП»,
  «+ Документ» и «Скачать всё» (текстом со значком, сплошной рамкой). КП — блоками по группам версий, между блоками 8px:
  у каждого полоса 3px слева цвета проверки текущей версии (зелёная, янтарная; «ждёт проверки» и
  «без проверки» — серые, как в «Проверке КП»), **фон и рамки не красятся**; подписи «КП 1»,
  «КП 2» (12/16, 500) — только когда КП несколько. Версии внутри блока — по порядку загрузки, с
  меткой «в1», «в2» (текущая — акцентом), прежние приглушены и помечены «заменена дд.мм.гг».
  Строка файла: имя **в одну строку** (основа — многоточием, расширение видно, полное имя, тип и
  размер — в подсказке; нажатие — просмотр), «Скачать» и «Удалить» 24px («Удалить» — по
  наведению); у текущей версии КП — это ВОР подрядчика — «Скачать» кнопкой с подписью и акцентной
  рамкой, у прежних версий и документов — значком; под ним одной строкой 12/16 серым — дата «дд.мм.гг» и время, кто загрузил
  («Фамилия И. О.»), метка в «ёлочках», вердикт цветным словом (вес обычный; кто и когда — в
  подсказке) и шаги «в сводной» / «к отправке подрядчику» (только у текущей версии); замечания —
  строкой с многоточием. Документы — своим списком с нейтральной полосой, больше трёх — свёрнуты
  под «Документы · N». Галочка «Свернуть всё» над таблицей (справа от «Копировать email», в
  карточке — у «Пригласить участников»; общая, помнится в браузере) сворачивает весь тендер:
  подрядчик — в две строки (`tc-table.is-compact`): КП — сводкой, под ней документы и
  «проверено / замечания / на проверке» по текущим версиям; первый контакт — ФИО и телефон,
  «ещё N» (все — в подсказке); вида работ нет; примечание — одной строкой. Стрелка сводки
  раскрывает КП одного участника. Данные 13/18, подписи 12/16 — свои rem, одни в реестре и
  карточке. **Статус участника** — `ParticipantStatusSelect`: плашка с точкой, 12/16 500, цвета —
  классы `tc-st-<статус>` (свои для тёмной темы, контраст ≥ 4,5:1), без права правки — та же
  плашка без стрелки, не бледная.
- **Мелкие действия в строку:** «Открыть», правка ссылки и документы (скрепка
  со счётчиком) — одной строкой (`.phase-actions`, `.phase-cell--actions`;
  без плотного реестра обёртка `display: contents`, вид прежний). Статус,
  срок, ответственный и «Проверка РД» — своими строками.
- Заголовок «Действия» над колонкой иконок — видимый.

### Плотный вариант: реестр «Планы затрат»

Класс `cp-dense` на корне `CostPlansPage` (те же классы `.cost-plans-page`
использует «ВОРы и РД» — там класса нет, вид не меняется). Правила — в конце
`CostPlansPage.css`.

- **Сетка и зебра вернулись**: тонкие вертикальные разделители (рамка 55%) и
  очень лёгкая подложка чётных строк. Общий слой их снимает (`border: 0`,
  `tr:nth-child(even) { background: none }`), поэтому правила продублированы
  в плотном варианте — в таблице десять узких колонок, взгляд по строке без
  подложки соскальзывает.
- **Шапка**: зелёный маркер раздела 3px и очень мягкая зелёная подложка, без
  градиента; высота не выросла (8px по вертикали).
- **Описание работ — ссылка** в карточку тендера: `--ui-link`, 500, тонкое
  подчёркивание. Кнопка пути к папке под ним — отдельное действие.
- **Без переносов по слогам** (`hyphens: manual`): «внутридворо-/вых» давал
  общий слой.
- **Примечание** — видно, что это поле: мягкая подложка и рамка, при
  наведении и фокусе заметнее; сохранение по потере фокуса не менялось.
  Поле бледнее заходит в отступ ячейки на 4px, чтобы не касаться разделителя.
- **Ширины** (rem): № 4, Объект 9, Описание 16 (окно шире — все пропорционально),
  Ответственный 9.5, Начало 6, Окончание 6, Срок плана 13.75 (замер по
  «21.12.2026 — 15.01.2027»), План затрат 6.5, Статус 8.5, Примечание 13;
  `min-width` таблицы 92.25rem.

### Плотный вариант: реестр «Тендеры на материалы»

Та же шкала, что у «Основного строительства», но свой класс — `tp-dense-mat`
на корне `TendersPage` (ставится при `isMaterialsView`), правила — в конце
`TendersRegistryPolish.css`. Класс `tp-dense` сюда не переносить: там другой
состав колонок и раскрытая строка с участниками.

- **Описание работ — видимая ссылка** в тендер основного строительства:
  `--ui-link`, 500, тонкое подчёркивание (при наведении — сплошное). Общее
  правило `.tp-desc-link` подчёркивание снимает — в реестре на сотни строк
  переход должен считываться сразу. «Показать полностью» — отдельной кнопкой.

  Ширина описания — то место, что ему оставалось в самом узком окне без
  прокрутки, поэтому у таблицы `min-width` = сумма колонок. Окно шире суммы —
  браузер растягивает **все колонки пропорционально** их ширинам. Ширины
  считаются по **замерам текста** (самая длинная плашка, дата, сумма), а не
  поровну. Если окно уже — **прокручивается таблица**, страница целиком — нет.
  Добавили или расширили колонку — пересчитать `min-width` (сумма указана в
  комментарии). Сетка у каждой таблицы своя. Колонку без ширины («остаток») не
  заводить: всё свободное место уйдёт в неё одну. Проверка — «свернули меню —
  все столбцы реестров растут пропорционально» в `tests/tender/sidebar-collapse.test.mjs`.
  Человек меняет ширины сам (перетаскиванием границ в заголовке) пока только в
  «Заявке на ДС» — `useColumnWidths` + `ColumnResizeHandle`, см. её раздел.
- **Не обрезать многоточием** даты, диапазоны, суммы, количества, номера
  документов. Диапазон в узкой колонке переносится **только после тире**
  (`breakAfterDash`: «21.12.2026 —» / «15.01.2027»); номер документа — только
  после разделителей (`BreakableId`: «ДС-2026/» / «0457-А»).
- **Длинное описание** — `ClampText`: до 3 строк, дальше кнопка
  «Показать полностью» / «Свернуть» (`aria-expanded`, мышь и клавиатура).
  Полный текст всегда в DOM. Если описание — ссылка в карточку, ссылкой
  остаётся сам текст, а кнопка раскрытия — отдельно (`wrap`).
  **Замер «не помещается» — пачкой на всю таблицу** (`src/utils/clampMeasure.js`,
  пока подключён в «ВОРах и РД»): чтение `scrollHeight` заставляет браузер
  пересчитать раскладку, и когда это делает каждая строка сама, на реестре в
  три сотни строк уходит около секунды — профиль показывал 39 % времени ровно
  на этом. В `clampMeasure` сначала идут все чтения, потом все ответы, и один
  общий `ResizeObserver` вместо одного на строку.
- **Наименование строки** (описание работ) — ссылка-заголовок `.ui-title-link`:
  тёмный текст 500, при наведении — цвет ссылки и подчёркивание. Остальные
  переходы («Открыть», объект) — обычные ссылки 400 цвета `--ui-link`.
- **ФИО в ячейке — «Фамилия И. О.»** (`PersonName`): короткое видимое
  (`aria-hidden`), полное — в `title` и в `.ui-sr-only` для диктора. Инициалы —
  неразрывная группа: перенос только между фамилией и инициалами.
  Должность/роль — вторичной строкой. Поиск, фильтры и выгрузка — по полному
  значению. Аватары не добавлять.
- **Пустые значения** — словом («Не назначен», «Не указан») или «—»,
  вес 400, `--text-secondary`, без курсива и декоративных тире. Ноль — «0,00»,
  «без изменений» — отдельно от пустого. Предупреждения об обязательных полях
  (`.vor-resp-empty.is-alert`, «⚠ Нет ссылки», «не из реестра снабжения») не
  убирать.
- **Статусы** — компактные плашки по содержимому: 13/18, 500, радиус 12px
  (длинный статус переносится внутри плашки), цвета — прежние (у каждого
  статуса свой смысл). Цвет не единственный признак — всегда есть подпись.
- **Кнопки-иконки** — 28×28 (в плотном реестре 26×26), SVG 16px из
  `ActionIcons`, обязательно `aria-label`. Эмодзи в интерфейсе не используем.
- **Выравнивание колонки действий** задавать только прямым ячейкам таблицы
  (`> tbody > tr > td.actions-cell`): селектор вида `td:last-child` задевает
  раскрытую строку и вложенные таблицы.
- **Цвет-признак на уровне ячейки** (`td.is-overdue` и т.п.) пишется с
  префиксом таблицы: общее правило цвета ячейки его перебивает.
- **Нативный select** не переносит текст: если значение может не поместиться,
  используем `WrapSelect` (видимая плашка-текст + прозрачный select поверх —
  клик, клавиатура и диктор работают как с обычным select).

## Поля, фокус, контраст

- `button`, `input`, `select`, `textarea` наследуют шрифт (`font-family: inherit`).
- Видимый фокус: `outline: 2px solid var(--primary-color); outline-offset: 2px`
  для `:focus-visible`.
- Контраст текста — не ниже 4,5:1 (крупного — 3:1), в обеих темах:
  - `--primary-color` (#0891b2) на белом — 3,7:1, для **текста** не годится:
    ссылки и «Показать полностью» — `--ui-link` (#0e7490, 5,4:1; в тёмной теме —
    `--primary-color`). Для рамок, линий и подчёркивания вкладок — `--primary-color`.
  - `--text-tertiary` на подсвеченной строке (просрочка) — ниже 4,5:1: для
    текста берём `--text-secondary`; `--text-tertiary` — только значки.
  - Текст статусов — на ступень темнее заливки того же оттенка.
- `.ui-sr-only` прижат к углу контейнера (`top/left: 0`): иначе в
  прокручиваемой таблице он расширял бы документ.

## Всплывающие элементы

Списки фильтров (`FilterDropdown`), меню статуса (`StatusDropdown`), окошко
срока (`DateRangeCell`) и срок заявки (`DeadlinePopover`) рисуются порталом в
`<body>`. Пока раздел открыт, на `<body>` висит `ui-work-portal`
(`useBodyClass`); правила порталов — под `body.ui-work-portal`. Окна
(`modal-overlay`) рисуются внутри корня страницы и наследуют шрифт.

## Откат

1. Убрать класс `ui-work` с корня страницы (для тендеров — `uiWork = false`) и
   вызов `useBodyClass('ui-work-portal')`: общий слой перестанет действовать.
2. Полностью — удалить импорты `../styles/workUi.css` и блоки `.ui-work` в CSS
   страниц. Разметочные правки (`ClampText`, `PersonName`, SVG-иконки,
   `colgroup`) работают и на прежних стилях.
3. «ВОРы и РД» (этап 1): убрать импорты `fonts.css`, `workUi.css`,
   `VorsTypography.css` из `VorsPage.jsx`.
