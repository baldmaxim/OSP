# Изменения БД

- SQL новой базы Яндекса не предполагает роли Supabase; соблюдать `migration/yandex/README.md`. Для нужных изменений вести обе миграционные линии, если явно не указано «только Яндекс».
- Не копировать из исторической документации пример permissive `RLS FOR ALL USING (true)` как текущую политику; проверить ограничения ролей, охват объектов, триггеры и фактические права.
- Новая схема = миграция + проверка + обоснованный откат + точечные тесты; схемы в `supabase/schemas/` — вспомогательные. Не считать наличие файла признаком выкладки.
- Тестировать на временной базе/проверенной копии. Не применять миграции к серверу без прямой задачи и согласования сессий перед выкаткой.
