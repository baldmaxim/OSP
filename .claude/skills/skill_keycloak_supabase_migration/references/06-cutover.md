# 06. Окно переключения входа (фаза B), откат, работа после

Предпосылки:
- фаза A завершена: БД в кластере, backend работает в `AUTH_MODE=supabase`;
- клиент `<portal>` заведён;
- репетиционный раунд пройден, `apply-mapping --dry-run` на стенде без конфликтов.

## Подготовка (T−7…T−1)
- [ ] Стенд в режиме `keycloak` проверен на тестовых учётках auth: вход, гейт, выход, SSO.
- [ ] `apply-mapping` и `merge-duplicates` прогнаны на копии прод-БД; отчёты согласованы с auth.
- [ ] Согласованы с auth: время окна, длительность финального раунда, кто на связи.
- [ ] Готова памятка пользователям (ниже) и разослано объявление.
- [ ] Записаны критерии отката и кто принимает решение.
- [ ] Свежий бэкап БД портала (снимок кластера или дамп) перед окном.

## Окно (T0)
1. **Заморозка в Supabase.** Отключить регистрацию (Auth settings → disable signups). Скрыть в портале
   смену пароля и профиля. Портал — в режим обслуживания или только на чтение.
2. **Финальный список.** `export-portal-users --round final` → счётчики показать человеку → передать
   auth.
3. **Работа auth** (портал ждёт): сопоставление, импорт недостающих, выдача `access`, финальный
   `su10-portal-mapping`.
4. **Применение.** `apply-mapping --dry-run --report …` → **СТОП:** человек смотрит отчёт (конфликты = 0,
   «записи под риском» объяснимы) → `apply-mapping`.
5. **Дубли.** `merge-duplicates --dry-run` → **СТОП** → `merge-duplicates`, если есть `duplicate_of`.
6. **Проверка покрытия** (`03-identity-mapping.md` §7). Без связи остались только ожидаемые.
7. **Переключение.** `AUTH_MODE=keycloak`, деплой или рестарт. Старые сессии Supabase больше не
   принимаются.
8. **Смоук.** Каждый пункт проверяет живой человек:
   - [ ] `linked_existing` (сотрудник из ФОТ) входит с паролем ФОТ и видит **свои прежние** документы;
   - [ ] `imported` входит с прежним паролем портала и видит свои документы;
   - [ ] пользователь без роли `access` → 403 `no_access`;
   - [ ] прежний пользователь без связи (`pending`) → 403 `pending_mapping`, пустая учётка не создана;
   - [ ] новый человек с ролью `access` → JIT, пустое рабочее пространство;
   - [ ] RLS: чужие документы не видны (прямой запрос API к чужой записи → 404 или 403);
   - [ ] SSO: вход в витрину `auth.su10.ru` → переход в портал без повторного пароля;
   - [ ] выход завершает сессию Keycloak (повторный вход спрашивает пароль);
   - [ ] обновление токена: через 5+ минут работы нет разлогинивания.
9. **СТОП:** смоук прошёл — открыть портал. Не прошёл — решение об откате.

## Откат
- **Когда:** массово не видны прежние документы; вход не работает; ошибки резолва.
- **Как:** `AUTH_MODE=supabase` и деплой, снять заморозку Supabase Auth. БД та же: данные, внесённые
  после переключения, сохраняются.
- **Цена:** пользователи, созданные через JIT в режиме `keycloak`, в режиме `supabase` войти не смогут.
- Связи в `user_identity_links` при откате не удалять: они понадобятся при повторной попытке.

## После переключения
- **Ежедневно первую неделю, дальше еженедельно:**
  - список 403 `pending_mapping` (`sub`, `legacyUserId`, без email в логах) → auth → новая версия
    файла → `apply-mapping`;
  - доля связанных прежних пользователей с заполненным `last_seen_at`.
- **Решения `pending`** из файла держать в трекере, пока не станут окончательными.
- **Не меньше 30 дней** Supabase живёт без изменений, только на чтение. Затем по решению человека:
  - удалить режим `supabase` и supabase-js из кода, env `SUPABASE_*`;
  - остановить проект Supabase (решает владелец портала);
  - удалить выгрузки и пароль шифрования по договорённости с auth.

## Памятка пользователям (шаблон)
> С <дата> вход в <Портал> — через единый вход su10 (`auth.su10.ru`). Ваши документы и данные
> сохранены.
> - **Сотрудники компании:** логин — рабочий email, пароль — **тот же, что в ФОТ**.
> - **Внешние пользователи портала:** логин — ваш email, пароль — **прежний пароль портала**.
> - Забыли пароль или не получается войти — обратитесь в поддержку <контакт>. Самостоятельный сброс
>   пароля пока недоступен.
> - Если после входа видите «учётная запись ожидает сопоставления» — напишите в поддержку, мы
>   подключим ваши данные.
> - Сменить пароль можно в личном кабинете `auth.su10.ru`.
