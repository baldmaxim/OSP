# Перенос учёток и паролей для своего входа tender.su10.ru

Свой вход нового портала: учётки — в `auth.users` базы Яндекса (те же идентификаторы, что в Supabase), пароли —
в закрытой схеме `osp_auth` (только отметка `osp:auth`, зашифрованы ключом сервера `OSP_AUTH_KEYS`), сессии — в
`osp_session`. Устройство — `server/osp-api/README.md` («Свой вход»), порядок действий — `migration/CUTOVER.md`
(«Свой вход tender.su10.ru»). Вход на osp.root.sx не меняется: он остаётся в Supabase.

## Путь отпечатков паролей

```
Supabase ──backup.sh --credentials──▶ *.auth-credentials.sealed ──scp──▶ corp: accounts/in/ ──accounts-sync──▶ osp_auth
           (поток psql → seal.mjs: на диске         (запечатано открытым       (prepare.mjs: распечатать закрытым
            только запечатанный файл)                ключом переноса corp)       ключом, зашифровать ключом сервера)
```

- **Ключ переноса** — пара RSA-3072 на corp (`deploy-server.sh transfer-key-init`): закрытый — только
  `secrets/accounts-transfer.key`, открытый — на машину, где снимается копия Supabase. После переключения —
  `transfer-key-destroy`.
- **Опись** `*.auth-credentials.manifest.json` — число строк, sha256, отпечаток учёток; ни почт, ни отпечатков.
- **Отпечаток учёток** — sha256 по учёткам (id, почта, сумма отпечатка пароля, подтверждение, блокировка,
  удаление); по нему видно, менялись ли учётки после выгрузки.

## Команды

| Где | Команда | Что делает |
|---|---|---|
| машина сборки | `bash migration/backup/backup.sh --credentials <открытый ключ.pem> [--accounts-only]` | копия Supabase (только чтение) с запечатанными паролями; `--accounts-only` — без данных |
| corp | `deploy-server.sh accounts-sync --users <файл> --credentials <файл> [--manifest <файл>] [--restore <uuid>] [--yes]` | перенос (сначала проверка с откатом, затем — по вопросу или `--yes`) |
| corp | `deploy-server.sh accounts-check` | готов ли свой вход: полнота учёток, пароли одобренных, канарейка ключа |

Перенос (`accounts-sync.sh`, `sql/sync.sql`) — одна транзакция, повтор безопасен:

- учётки: новые добавляются; у существующих обновляются почта, подтверждение, данные регистрации; удалённые в
  Supabase и удалённые администратором в новом портале (надгробия `osp_auth.tombstones`) не воссоздаются —
  вернуть одну: `--restore <uuid>`;
- пароли: новые — вставка; изменённые в Supabase после прошлой копии — замена только у паролей, заданных в
  Supabase (сессии со старым отзываются); заданные в новом портале (смена, временный от администратора) не
  трогаются. Вход пересчитывает отпечаток в scrypt, но источник пароля не меняет;
- дубли почты (после нормализации) — остановка до записи;
- с `--yes`: снимок соседей и копия базы до записи, сравнение соседей после.

Перенос нужен до переключения tender.su10.ru на свой вход (пилот и последняя копия прямо перед переключением).
После переключения пароли нового портала живут только в базе Яндекса — синхронизацию с Supabase не запускают.

Проверки: `tests/backup/own-auth-accounts.test.mjs` (от «прода» Supabase до входа в osp-api прежним паролем).
