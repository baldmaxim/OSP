# Заявка команде auth — портал ОСП (`osp`)

> **Перед отправкой заполнить** поля в `<…>`: домен — после согласования с владельцами контура; контакт;
> даты — после стенда. Счётчики подставлены по q3 от 2026-10-08.

**Портал:** ОСП — отдел сопровождения подрядчиков: тендеры, договоры, расценки, кабинет подрядчика.
**Что происходит:** портал переходит со входа Supabase на Keycloak su10 по стандарту
`skill_keycloak_supabase_migration` (форматы файлов — `05-auth-handoff.md`). Вход через Keycloak
включается одновременно с переездом портала на новый домен — одним окном.
**Контакт со стороны портала:** <ФИО, канал>.

## 1. Клиент (шаблон стандарта)

```
Портал: ОСП (отдел сопровождения подрядчиков)     client-id: osp
Прод:   https://<osp-domain>
Стенд:  https://stage.<osp-domain>
Callback:     https://<osp-domain>/api/auth/oidc/callback        (+ стенд)
Post-logout:  https://<osp-domain>/                               (+ стенд)
Web origins:  https://<osp-domain>                                (+ стенд)
Гейт: client-роль osp:access
Плитка в витрине auth.su10.ru: «ОСП — сопровождение подрядчиков», «Тендеры, договоры и расценки подрядчиков», https://<osp-domain>/
Получатель секрета: <ФИО/контакт>, канал: <защищённый канал>
Даты: репетиционный раунд <…>, окно переключения <…>
```

Как у действующих порталов: confidential, Standard flow, PKCE S256, без direct grant; точные redirect
URI и web-origins без `*`; мапперы `aud=osp`, `email`, `preferred_username`, client-роли в
`resource_access.osp.roles` (access token).

## 2. Кто пользуется порталом (только счётчики)

| Категория | Сколько | Как, по нашему пониманию, будут входить — решаете вы |
|---|---|---|
| Сотрудники СУ-10 | 85 учёток, из них одобрены 74 | рабочий email + пароль ФОТ (`linked_existing`) |
| Подрядчики — внешние организации, в ФОТ их нет | 0 (регистрация подрядчиков на паузе) | прежний пароль портала: заводятся с bcrypt-хешем из Supabase (`imported`) |
| Без пароля в Supabase | 0 | временный пароль от вас (`imported_no_password`) |
| Входили за последние 180 дней | 82 (за 30 дней — 55) | — |

Подробности по каждому пользователю — в зашифрованном списке `su10-portal-users`, по стандарту.

## 3. Что просим

1. Клиент `osp` для прода и стенда, роль `osp:access`, мапперы, плитка — по разделу 1.
2. Client secret — защищённым каналом получателю из раздела 1.
3. **Тестовые учётки для стенда:** сотрудник из ФОТ; подрядчик, заведённый с паролем; учётка без
   `osp:access`; учётка, которой не будет в файле сопоставления.
4. **Сроки:** когда сможете обработать репетиционный и финальный раунды; сколько длится обработка
   финального раунда — от этого зависит длина окна переключения.
5. **Канал** для зашифрованных файлов и, отдельно, для пароля шифрования.

## 4. Вопросы

1. **Пароль ФОТ.** Все ли сотрудники его знают? Часть сотрудников ФОТ может не открывать. Как им
   получить или восстановить пароль до окна — нужно для памятки.
2. **Разные email в портале и в ФОТ** у одного сотрудника: как будете решать, что нужно от нас.
3. **Новые подрядчики после переезда.** Самостоятельной регистрации в su10 нет. Сейчас подрядчики
   регистрируются в портале сами, администратор ОСП их одобряет. Предлагаем так: администратор ОСП
   создаёт в портале приглашение (email, организация, роль) и отправляет вам заявку на учётку. Какой
   канал и срок заведения учётки вас устраивает?
4. **Сброс пароля** после переезда — только через вас. Куда направлять пользователей ОСП (контакт для
   памятки)?
5. **После переключения** мы ежедневно в первую неделю присылаем список тех, кого не нашлось в файле
   сопоставления (403 «ожидает сопоставления»). Как быстро сможете выпускать новую версию файла?
6. **Ключи подписи realm.** Какой алгоритм подписи access token (RS256?) и как проходит ротация ключей:
   предупреждаете ли заранее, сколько живёт прежний ключ в JWKS. Мы проверяем `iss`, `aud=osp`, `azp`,
   `exp` и подпись по JWKS с обновлением кэша при незнакомом `kid`.
7. **Окно отката.** Если после переключения придётся вернуть прежний вход (до 7 дней), клиент `osp` и
   связи остаются как есть — подтвердите, что с вашей стороны ничего откатывать не нужно.
