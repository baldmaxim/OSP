# Инвентаризация Supabase (этап 0)

Четыре запроса собирают то, что нельзя узнать из кода: реальную схему прода, политики, права
функций, счётчики пользователей, задачи cron, Storage, применённые миграции.

## Что они делают и чего не делают

- Каждый файл — **один SELECT**. Ничего не создаёт, не меняет, не блокирует.
- Ответ — **одна ячейка JSON**.
- **Персональных данных нет:** ни email, ни id, ни хешей паролей — только счётчики и имена объектов.
  Исключение — домены почты сотрудников, на которых не меньше 3 человек (`su10.ru` и т. п.).
- **Секретов нет:** у cron — только имя и расписание (текст команды не выводится), у vault — только
  имена, у настроек ролей — имена параметров и значения таймаутов.
- Проверены на PostgreSQL 17 с заглушками схем Supabase в режиме `default_transaction_read_only=on`.

| Файл | Что собирает |
|---|---|
| `q1_environment.sql` | версия PG, collation, timezone, расширения, таблицы (объём, PK, RLS, триггеры, `updated_at`), представления, последовательности, FK в чужие схемы, DEFAULT с `auth.*`, триггеры на `auth.users`, типы колонок |
| `q2_security.sql` | все политики, политики для `anon`, широкие `USING (true)`, таблицы без RLS, функции (SECURITY DEFINER, `search_path`, кто может вызвать), что доступно `anon`, таймауты ролей, публикация Realtime |
| `q3_users.sql` | счётчики `auth.users` и `user_roles`, провайдеры, дубли email (только число), категории входа после окна B, колонки-владельцы и «висячие» id |
| `q4_services.sql` | cron, Storage, имена секретов vault, применённые миграции, кто подключён к базе, подготовленные транзакции, слоты репликации |

## Как запустить (ваш компьютер)

1. Supabase → проект ОСП → **SQL Editor** → New query.
2. Вставить содержимое `q1_environment.sql` целиком → **Run**.
3. Нажать на ячейку результата → скопировать значение.
4. Повторить для `q2`, `q3`, `q4`.

Если удобнее `psql` (строку подключения не показывать и не вставлять в чат):

```powershell
$env:PGOPTIONS = "-c default_transaction_read_only=on"
psql $env:SUPABASE_DB_URL -At -f migration/inventory/q1_environment.sql | Out-File -Encoding utf8 q1.json
```

## Как передать результат

Любой из способов — ответы не содержат персональных данных и секретов:
- вставить JSON в чат (по одному запросу в сообщении);
- или положить файлы `q1.json` … `q4.json` на удалённую машину через `scp` в
  `migration/inventory/results/` (каталог в `.gitignore`).

По ответам я заполню `migration/inventory.md` — это и есть материал для **СТОП 1**.
